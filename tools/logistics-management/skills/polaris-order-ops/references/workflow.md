# 跨境订单履约与单据工作流参考

## 1. 目标

在没有现成电商后台时，先建立一套最小可运行的订单履约与单据流程，使每一笔业务都可以被追踪、核对和归档。

## 2. 角色口径

- 销售方：公司
- 供货方：供应商或合作方
- 终端客户：海外购买方或下单方
- 物流服务方：跨境物流供应商

如具体订单与以上口径不一致，先单独说明，不要直接套模板。

## 3. 订单管理结构

订单管理按订单号维护既有业务记录：

```text
订单管理/<order_no>/
  meta.json
  报价/meta.json
  报检/meta.json
  收款/meta.json
  发货/meta.json
  开票/meta.json
  对账/meta.json
  归档/meta.json
  附件/meta.json
```

订单主 `meta.json` 保存订单本体和关键状态汇总。报价、报检、收款、发货、开票、对账、归档、附件各自使用独立 `meta.json`。

## 4. 最小合规链路

一笔业务按以下链路核对：

1. 订单记录
2. 报价记录
3. 报检记录
4. 收款记录
5. 发货记录
6. 开票记录
7. 对账记录
8. 归档位置

## 5. 实操顺序

### 第一步：维护订单主记录

订单号来自既有业务记录，不在本流程里新建空订单。

字段建议：

- 订单号
- 下单日期
- 客户名称
- 客户国家
- 联系方式
- 销售渠道
- 商品名称
- 数量
- 币种
- 成交金额
- 收款状态
- 发货状态
- 对账状态
- 归档状态
- 备注

### 第二步：建报价记录

报价单独保存在 `报价/meta.json`。

报价前先确认产品市场标价。产品 `list_price` 不使用单一倍率；先看内部成本 `purchase_price + packaging_price + labor_price`，再结合品类、用途、寓意、体量和心理价位确定。货号 43 的 `389 CNY` 是强寓意挂坠的品牌锚点价，只能作为同类寓意款参考，不能反推所有产品价格。

内部计算口径：

- 单品基础成本：`base_cost = purchase_price + packaging_price + labor_price`
- 订单已知毛利：`known_gross_profit = customer_payable - sum(base_cost * quantity)`
- 订单实际利润：`actual_profit = customer_payable - product_costs - actual_shipping_cost - payment_fee - other_loss`
- 毛利率：`gross_margin = known_gross_profit / customer_payable`

报价单面向客户时，只能展示客户需要确认的信息：商品、数量、币种、报价金额、运费、客户应付总额和必要的交付说明。进价、利润、倍率、定价公式、内部推导、旧数据纠错、对话记录等只能放在内部 `meta.json`、对账记录或内部备注中，不能进入客户可见 PDF/HTML。

字段建议：

- 报价单号
- 订单号
- 报价日期
- 有效期
- 币种
- 商品行
- 运费
- 客户应付总额
- 报价单文件位置

### 第三步：建收款记录

收款信息写入 `收款/meta.json`。付款凭证文件放在 `收款/` 或 `附件/` 下，再把路径写入 `proof_documents`。

字段建议：

- 收款状态
- 应收金额
- 实收金额
- 收款方式
- 收款时间
- 汇率
- 收款凭证路径
- 备注

### 第四步：建报检记录

报检单独保存在 `报检/meta.json`。

字段建议：

- 报检单号
- 订单号
- 报检日期
- 商品明细
- 外观检查结果
- 包装检查结果
- 标签/配件检查结果
- 问题记录
- 报检结论

### 第五步：建发货记录

发货流程状态和发货明细写入 `发货/meta.json`。

字段建议：

- 订单号
- 收货人
- 目的国
- 包裹件数
- 预估重量
- 实际重量
- 物流商
- 物流渠道
- 运单号
- 发货日期
- 运费
- 签收状态

### 第六步：建开票记录

开票信息单独保存在 `开票/meta.json`。

字段建议：

- 订单号
- 是否申请开票
- 发票类型
- 购方名称
- 税号/证件号
- 开票内容
- 开票金额
- 收票邮箱
- 申请日期
- 开票日期
- 发票号码
- 状态

### 第七步：建对账记录

对账信息写入 `对账/meta.json`。

核心核对关系：

- 销售订单金额
- 客户实收金额
- 应付供应商货款
- 国际物流费用
- 平台或支付通道费用
- 是否已开发票

### 第八步：建归档记录

归档状态写入 `归档/meta.json`，归档材料放在 `归档/` 或 `附件/` 中。

字段建议：

- 归档状态
- 归档日期
- 归档位置
- 归档文件清单

## 6. 单笔订单所需最小输入

如要开始处理一笔单，至少收集：

- 客户名称
- 商品名称
- 数量
- 成交金额和币种
- 收货国家
- 是否已付款
- 是否需要发票

如果以上信息不全，先做信息收集，不直接进入开票或发货。
