# 产品分析方法

当 `analysis.entry_route` 为 `product-analysis` 时使用。本方法用于把产品观察转成
可验证的定位、价值承诺、使用场景和优先实验，不改变情报分析的冻结证据、复核和
`output.json` 契约。

## 分析对象

先明确产品对象、目标用户或购买者、使用/赠礼场景、市场范围和当前决策。不要把产品
属性、用户感受、市场信号和建议混为一类。

将观察分为四层：

1. 产品事实：材料、尺寸、功能、工艺、价格和可获得性等可直接观察的属性。
2. 产品线索：使用场景、问题解决方式、审美或信任信号、比较对象和评论反馈。
3. 产品解释：某属性为什么可能对特定人群或场景有价值。
4. 产品决策：应优先验证、强化、调整或放弃的价值主张与下一步实验。

## 核心模块

按问题选择少量模块，而不是固定全做：

- **定位与价值承诺**：从反复出现的功能、材料、工艺、文化、礼赠或风格线索中提出
  3–5 个一句话承诺；每个承诺都标注适用人群、场景、证据和边界。
- **场景与任务**：识别用户试图完成的任务、触发时刻、决策摩擦和替代方案；区分事实
  观察与推断的需求。
- **差异化与替代**：比较产品与可观察替代品在能力、感知价值、使用成本、信任和限制上
  的差异；不把没有证据的“独特”当成结论。
- **产品表达系统**：当问题涉及展示或内容时，分析产品角度、证据形式、视觉/文字入口、
  格式角色和可复用模板，而不把内容表现误写为产品质量。
- **可观察转化路径**：仅使用可见的询问、收藏、分享、评论或其他行为代理；不得将其
  表述为订单、GMV 或真实转化。
- **迭代实验**：将强度不足的判断转为可测试假设，写明变量、样本、衡量指标、成功阈值、
  反证和停止条件。

## 输出结构

每项产品主张使用同一结构：

```text
主张 → 证据 → 解释 → 比较或替代 → 限制 → 下一步验证
```

最终建议应回答：优先服务谁、主打什么价值承诺、在哪个场景验证、以何种产品或表达变体
测试、什么结果会改变当前判断。

## 证据与复核规则

- 每个产品事实和例证都必须绑定冻结 observation。
- 同一主张尽量由两种以上可观察证据支持，例如属性文本、视觉/媒体、评论、比较或公开
  指标；缺少时必须降低主张强度。
- 产品主张、内容主张和市场主张必须分开分类，避免把互动表现推断为产品—市场匹配。
- 涉及安全、合规、耐久、产地、价格、供货或不可逆产品投入的结论，应提高风险等级并
  进入人工复核。
