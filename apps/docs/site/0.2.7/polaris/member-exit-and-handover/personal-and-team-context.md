# Personal And Team Context

This document explains how Polaris separates personal memory from team-owned
project context.

## Two Different Questions

When a member leaves, there are two different questions:

- which parts of personal working experience remain theirs
- which parts of project and environment context must stay with the team

## What Your Team Gets

Polaris currently separates:

- user memory for person-specific working patterns
- workspace memory for project and environment knowledge
- session memory snapshots for handover context
- review-oriented memory flow for deciding what should be retained

## Why It Matters

This is what helps teams preserve:

- handover context
- environment fixes
- validation recipes
- project operating knowledge

without treating every personal habit as a team asset.
