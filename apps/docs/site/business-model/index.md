# 业务模式

这一部分定义 Polaris 面向的客户、业务结果和商业化边界。

## 核心判断

Polaris 面向的是**稳定业务流程的业务处理团队**。

这类团队已经知道业务应该怎样处理，但现有方式通常依赖：

- 口头规则和个人经验
- 多个表格、聊天窗口和外部系统之间的人工搬运
- 人工复核、审批和异常处理
- 无法复用的脚本或一次性 AI 对话

他们需要的不是从空白画布搭建一个 agent，也不是单纯换一个聊天工具。
他们需要把重复的业务处理变成一套可以持续运行的工作单元：

1. 接收结构化或非结构化输入
2. 按明确步骤处理和调用外部系统
3. 在需要判断的地方交给合适的人复核
4. 处理失败、补充材料和例外分支
5. 交付结果并保留执行记录

Polaris 的产品定位是：

> 用灵活 [Polaris DSL](/polaris/dsl) 定义业务流程，用卡片式界面执行、复核和交接，
> 让重复业务处理稳定、可追踪、可恢复。

## 业务结果

| 业务结果 | 团队获得的能力 |
| --- | --- |
| 处理一致 | 同一类请求遵循同一套规则和步骤 |
| 处理可追踪 | 能看到输入、状态、负责人、输出和异常 |
| 处理可恢复 | 中断后可以重试、补料或从节点继续 |
| 处理可交接 | 工作状态不依赖某个员工的聊天记录或本地文件 |
| 处理可治理 | 权限、审批、凭证和外部调用有明确边界 |
