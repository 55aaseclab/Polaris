# 非目标客户与边界

## 为什么需要这页

稳定业务流程的业务处理团队和个人 AI 用户都可能使用相似的模型，
但购买理由完全不同。

如果把所有需求都归入“AI 产品”，Polaris 会同时追逐个人效率、
聊天体验、内容生成、coding agent 和企业流程，最终没有清晰的首个客户。

## 当前不优先服务的客户

### 个人用户

个人用户通常比较：

- 能否立即开始使用
- 对话和内容生成质量
- 文件上传、图片、语音和搜索
- 价格与设备体验

他们适合购买个人 assistant 或内容工具。
除非个人用户正在运营一条需要多人协作和记录的业务流程，否则不是
Polaris 的首个客户。

### 纯个人开发者

个人开发者更关心 IDE、CLI、模型响应速度和本地工作流。
Cursor、Copilot、Claude Code、Codex 等产品更直接地满足这一需求。

Polaris 可以承载 coding agent，但只在这些条件成立时优先：

- 共享环境需要权限和隔离
- 团队需要统一的执行流程
- 凭证、数据或项目状态不能散落在个人设备
- 需要交接、审计和稳定恢复

### 开放式 agent 实验

只想试验模型、工具调用或 prompt 的团队还没有稳定业务结果。
这类项目可以作为探索，但不应承诺业务生产，也不应成为产品路线图的
主要依据。

### 核心系统替代

需要完整 ERP、CRM、财务核心或行业生产系统的客户，通常要求长期数据
迁移、主数据治理和深度合规能力。
Polaris 的切入点应是围绕现有系统执行一条流程，而不是一次性替代整个
系统。

## 何时重新评估

非目标并不等于永久拒绝。
当客户同时出现以下信号时，可以重新评估：

- 个人任务已经形成多人重复处理的队列
- 结果需要审批、交付和审计
- 处理失败会造成明确业务成本
- 有流程负责人和可用的历史样本

此时客户已经从“使用一个 AI 工具”转向“运营一条业务流程”。

## 决策规则

遇到新需求时，先问五个问题：

1. 这件事是否重复发生？
2. 是否有明确的输入和交付结果？
3. 是否需要多人、人工复核或审批？
4. 失败后是否需要恢复、补料或交接？
5. 是否有人对处理结果负责？

四个问题以上回答“是”，进入业务流程评估。
否则保留为探索需求，不改变核心定位。
