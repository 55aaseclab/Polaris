# Polaris 2.0.0 本地部署需求

Status: future requirements. Not in 0.5.0 scope.

2.0.0 在云服务产品闭环经过验证后，提供企业本地部署和离线运行能力。
本页是需求池，不代表这些能力已经实现、承诺日期或通过生产验证。

## 进入条件

开始 2.0.0 前至少满足：

- 0.5.x 已验证统一 Workflow API、订阅状态机和运行回执。
- 至少一个商品化工作流在云端稳定运行，并有明确成本基线。
- 云端 pack、运行时和客户端协议已经版本化，可被本地版复用。
- 存在愿意共同验收本地部署、安全和升级要求的设计伙伴。

## 一、本地安装与拓扑（P0）

- 提供单机 10–20 席参考拓扑和明确的硬件容量表。
- 支持联网安装、半离线安装和完全离线镜像包。
- 安装前检查 CPU、内存、磁盘、端口和 Docker 网络池。
- 明确控制面、执行面、存储、网关和客户端的服务所有权。
- 客户本地版继续使用与云端一致的 WorkEnvelope 和 pack 契约。

## 二、本地身份与权限（P0）

- 提供不依赖云 IdP 的本地账号、管理员引导和会话管理。
- 支持密码或 passkey、邀请、禁用、重置、锁定和审计。
- 支持 OIDC 等企业身份联邦，但不建立第二套授权策略。
- 身份必须映射到同一租户、角色、Vault 和工作流所有权模型。
- `POLARIS_AUTH_MODE=disabled` 只用于开发测试，不可作为多用户方案。

## 三、隔离执行与容量（P0）

- 实现并验证真实托管 `mode: "vault"` 执行，不使用 mock 冒充。
- 支持批量创建、预热、停止、过期和销毁本地 Vault。
- 销毁必须覆盖容器、网络、卷、凭据和用户关联数据。
- 为至少 20 个活跃 Vault 验证资源与 Docker 网络池余量。
- 保留 pack digest、能力租约、artifact、receipt 和审计证据。

## 四、离线依赖与凭据（P0）

- 列出完全离线时可用、降级或不可用的模型和外部连接器。
- 支持客户自带模型端点、代理、证书和本地 secret backend。
- 安装包、镜像、pack 和升级包必须可校验签名与完整性。
- 日志和诊断包默认脱敏，不将本地凭据发送到 Polaris 云端。

## 五、运维生命周期（P0）

- 提供备份、恢复、升级、回滚、证书轮换和灾难恢复手册。
- 升级前验证数据库、pack、运行中任务和客户端协议兼容性。
- 管理员可查看活跃 Vault、容量、配额、失败和陈旧资源。
- 支持导出登录、授权、执行、拒绝和管理员操作的审计记录。
- 提供可重复的安装验收与升级演练，而不依赖手工 SSH 排查。

## 六、批量用户与短期队列（P1）

- 批量创建课程、考试、实验室或 PoC 用户及 Vault。
- 支持 TTL、到期提醒、冻结、延长和整组销毁。
- 提供 `lab-cell`、`course-cohort`、`exam-session` 和
  `delivery-pod` 配置模板。
- 场景模板只组合现有身份、配额和生命周期能力，不建立第二调度器。

## 七、本地版验收门槛

1. 在不访问外部 IdP 的情况下创建 20 个本地用户并完成登录与退出。
2. 20 个用户拥有相互隔离的 Vault，并通过跨租户拒绝测试。
3. 批量销毁后不遗留容器、网络、卷、凭据或身份映射。
4. 断网重启后，运行状态、订阅、产物和审计记录保持一致。
5. 备份可在干净环境恢复，升级失败可回滚到受支持版本。
6. 云端与本地版运行同一 pack 时遵守同一输入、输出和回执契约。

## 非目标

- 不为单个客户维护永久分叉的工作流运行时。
- 不在没有容量证据时承诺 50 或 100 席单机部署。
- 不把开发者本机启动脚本包装成企业本地部署产品。
- 不承诺离线环境可以调用本来依赖公网的第三方数据源。
