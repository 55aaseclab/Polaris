# Polaris 1.0.0 云端生产成熟度需求

Status: planned.

1.0.0 的目标不是继续增加能够演示的工作流功能，而是让已经验证的云端工作流
可以被用户长期依赖。0.5.x 负责建立云服务、小程序、Web、API 和首批商品化
工作流；1.0.0 负责把这些能力提升到稳定、可解释、可恢复和可审计的生产标准。

客户本地部署不属于 1.0.0，由
[Polaris 2.0.0](../polaris-2.0.0/) 单独跟踪。

## 核心判断

AI 让“构建应用”从稀缺能力变成了普遍能力，但“让业务流程可靠地长期运行”
仍然需要系统工程、业务建模和运营能力。

工作流服务的价值不再只是开发功能，而是保证流程：

- 可观测；
- 可恢复；
- 可审计；
- 可持续运行。

Polaris 1.0.0 的商业价值因此分为三个层次。

## 第一层：能跑

这是工作流服务成立的基础，也是 AI 工具已经大幅降低门槛的部分。

- 能创建工作流。
- 能调用 API。
- 能完成正常路径。
- 能看到结果。

仅达到这一层，可以证明功能可行，但不能证明系统适合长期承载真实业务。

### 验收要求

- Web、小程序和 API 使用同一套工作流定义与运行 API。
- 工作流输入、输出和正常完成条件有版本化契约。
- 每次执行有稳定的 run ID、状态和结果引用。
- 用户能从入口创建运行并查看最终结果。

## 第二层：跑得稳

这是大多数 Demo 与生产系统之间的差距，也是 1.0.0 的最低发布门槛。

- 有状态。
- 有重试。
- 有超时。
- 有幂等。
- 有错误处理。
- 有人工介入。
- 有监控。

### 验收要求

- 状态持久化，服务重启后不会丢失运行、订阅或等待中的人工任务。
- 每个外部调用定义超时、有限重试、退避策略和最终失败状态。
- 创建运行、执行有副作用的步骤和投递通知都支持幂等键。
- 业务错误、来源错误、系统错误和权限错误使用可区分的错误模型。
- 工作流可以暂停并进入人工复核、补料、批准或拒绝状态。
- 监控覆盖成功率、延迟、积压、重试、成本和依赖健康度。
- 局部失败不会破坏已确认状态，也不会产生重复副作用。

## 第三层：出了问题能解释和恢复

这是企业愿意持续付费的核心价值，也是 Polaris 区别于一次性 AI 自动化的地方。

- 能定位问题。
- 能复现运行。
- 能知道哪个版本执行。
- 能查看完整输入输出。
- 能从中断节点继续。
- 能回滚或补偿。
- 能证明谁做了什么。

### 验收要求

- 每次运行关联工作流版本、pack digest、模型配置和能力授权版本。
- 运行时间线记录节点输入、输出、状态变化、错误和外部调用回执。
- 敏感字段经过授权和脱敏后才能查看，审计能力不等于无限制暴露数据。
- 在依赖和配置仍可用时，可以用固定版本及输入重放一次运行。
- 失败运行可从安全检查点继续，不强制从头执行已确认的副作用。
- 不可回滚的步骤必须声明补偿动作或明确的人工处置路径。
- 用户、系统、管理员和 API 调用方的关键操作都记录主体、时间和原因。
- 运维人员能够从一次告警追踪到具体租户、订阅、运行、节点和依赖。

## 产品能力映射

| 价值层 | Polaris 核心对象 | 用户购买的结果 |
| --- | --- | --- |
| 能跑 | Flow、Run、Artifact | 工作流可以完成任务并交付结果 |
| 跑得稳 | Durable state、Retry、Timeout、Idempotency、Approval | 任务长期运行时不易丢失、重复或失控 |
| 能解释和恢复 | Version、Receipt、Checkpoint、Compensation、Audit | 出错后可以定位、继续、补偿并证明过程 |

## 1.0.0 发布门槛

1. 至少一个真实商品化工作流达到三层全部要求，而不只是正常路径演示。
2. 连续运行周期内的成功率、恢复率、重复副作用和通知丢失有量化证据。
3. 故障演练覆盖超时、依赖失败、进程重启、重复请求和人工任务中断。
4. 任意一次生产运行都能回答“谁、何时、用哪个版本、输入什么、输出什么”。
5. 至少验证一次从检查点恢复，以及一次回滚或补偿流程。
6. 用户和运维人员看到的是可行动的状态与错误，而不是内部堆栈或模糊失败。
7. 成本、质量和可靠性指标可以按工作流版本追踪，支持持续运营决策。

## 非目标

- 不以新增更多模型、连接器或界面数量代替可靠性建设。
- 不把只能完成 happy path 的流程标记为生产可用。
- 不承诺所有外部副作用都可回滚；不可逆操作必须有补偿或人工路径。
- 不为了完整追踪而在日志中暴露凭据或不必要的个人数据。
- 不在本版本交付客户自托管、离线安装或本地身份系统。

## 版本关系

| 版本 | 产品重点 |
| --- | --- |
| 0.5.x | 建立云服务入口、API、订阅运行时和首批商品化工作流 |
| **1.0.0** | 证明工作流能稳定运行，且故障可解释、可恢复、可审计 |
| 2.0.0 | 将已验证的云端契约扩展到企业本地和离线部署 |
